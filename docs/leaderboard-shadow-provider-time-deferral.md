# Normal shadow worker: provider-time deferral proposal

This is an offline wrapper-only change based on the installed protected `77a2c1a702e991db66eda813cbc3c1564872f902` runtime. It has not been deployed or activated. The protected Python worker bytes remain SHA-256 `b73bf918fdb9453d26933fafd39078616711462700c6618ac779d7e49187ffd6`.

The active host observer writes the Supabase disk provider's `utilization.timestamp` into `/var/lib/oddssearch/leaderboard-shadow-resource.json`. The observer may rewrite the file every two minutes while the provider observation itself advances about every six minutes. The worker's SQL refresh refuses evidence older than five minutes; a normal cron tick can therefore fail before opening a run during the stale interval. File mtime and API fetch time do not establish a new disk measurement.

The normal wrapper now takes its existing worker FD9 and database-heavy FD8 in the same order, then validates the **same selected file path** as the Python worker: `LEADERBOARD_SHADOW_RESOURCE_EVIDENCE_FILE`, or the shared default `/var/lib/oddssearch/leaderboard-shadow-resource.json`. It opens the file with `O_NOFOLLOW | O_NONBLOCK` so an invalid FIFO without a writer cannot hold both locks, then rejects nonregular files before reading. It requires exactly `disk_available_bytes` and `observed_at`, a positive integer disk value, a timezone-aware provider timestamp, and age from 0 through 210 seconds. Missing, malformed, future or older evidence returns the existing healthy deferral code 75, which the wrapper maps to exit 0. This 210-second admission margin leaves about 90 seconds before the unchanged 300-second SQL limit for the bounded 30-second worker and preflight. It is a wrapper scheduling margin, **not** a weaker database threshold or a claim that a later provider refresh occurred. Other validator failures remain errors.

Fresh evidence runs the exact existing `run-once --fixture-limit 250 --max-seconds 30 --capture-limit 250 --job-limit 250` command. The Python worker still reads the file, writes its actual provider timestamp through `refresh_external_resource_evidence_v2`, enforces the rolling/physical/importer resource guard before and during work, and records normal run/resource evidence. The wrapper does not call SQL, change any flag, update the file, or override Python's check. Source ingestion keeps the heavy-slot priority and busy-lock deferral; worker quarantine and cron-transition checks are unchanged.

The dormant finite/rolling supervisors remain outside the normal-path change.
