# Worker-only protected cron transition (review proposal)

**Offline artifact only.** This follow-up is based on frozen PR 102 and leaves its branch/head unchanged. It does not change the existing two-entry cutover verifier/installer. The source supervisor may hold `/var/lock/stats-reconciliation-supervisor.lock` continuously while idle; a worker-only switch must neither acquire that lock nor create the global `cron-transition.hold` that the source loop checks.

The new worker-only entrypoint verifies its full runtime manifest and protected lock defaults, then delegates one atomic install or recovery to its separate Python helper. The helper nonblock-acquires certification, `pins.json`, legacy worker/heavy, protected worker/heavy and canonical writer locks; it checks protected worker/heavy device/inode against the existing pins. The four existing `/var/lock` leaves admit the observed root-owned sticky `1777` parent and root-owned regular single-link lock files, while protected pins/locks and private crontab files retain strict private-parent checks. An active source batch owning heavy/canonical causes a clean refusal. The expected long-lived source supervisor remains scheduled and may keep its own supervisor lock. Both current and candidate source wrapper, common library and reconciliation Python bytes must match; the source cron line is unchanged exactly. Its canonical form includes the fixed `/etc/oddssearch/stats-export-transaction.url` read, the nonempty guard, and the `SUPABASE_DB_URL_SESSION` binding before the immutable source wrapper; changing or omitting any part is a refusal.

Before a future install, the lead must independently prove `worker_enabled=false`, `backfill_enabled=false`, no open worker run, source certification released, genuine disk/importer and rolling/physical guards still satisfactory, and preserve the exact original root crontab and digest. Prepare a private root-owned mode-0600 reviewed target crontab that changes **one active worker line** only from the old immutable ROOT to the new immutable ROOT, retaining cadence, command suffix and arguments. The active source line and every other byte stay identical. Supply both exact SHA-256 digests and canonical old/new release paths. The helper itself creates the worker-only hold under its locks before an atomic whole-crontab write; there is **no separate freeze edit**. It binds its own package ROOT to one transition endpoint and verifies both endpoint manifests and critical worker/common/source bytes before mutation.

The durable transition hold is an exclusively created root-owned `0600` **worker-only** `<protected-worker-lock>.quarantine` marker with a unique token, digests and device/inode. The worker wrapper refuses it; source's DB-heavy helper only checks `.quarantine.heavy`, which this tool never creates. Both legacy worker marker variants and the protected heavy marker must also be absent. The helper fsyncs its marker and directory **before** the whole-crontab write, revalidates held lock paths/pins before writes and cleanup, requires exact readback and second process check, and removes only its exact marker on success. If a write, readback or process check is uncertain, it leaves the marker. Recovery under the same barrier accepts only the exact original active or exact target digest, restores the original active bytes if necessary, verifies readback and removes only its own pinned marker. Reversal is a direct active-new→active-old install with ROOTs and reviewed digests exchanged; no manual cron state change is needed. An unexpected foreign marker, source change, lock holder or current crontab leaves all work stopped for the lead.

The helper intentionally does not query production SQL or modify flags; the lead's independent disabled-switch/open-run checks and post-cutover readback are required. A marker may remain after an interrupted transition; do not remove it outside exact owned recovery. A new immutable release and truthful future worker label are separate lead steps. Source importer release/baseline, queue/history, 5 GiB rolling WAL, 512 MiB rolling temp, Supabase 20 GiB free-disk guard, 250/30 worker bound, 48-hour soak and legacy customer reads remain unchanged. This artifact is not permission to deploy or activate.
